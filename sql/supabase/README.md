# Supabase memory RPC v1

Canonical SQL is in `src/memory/assets/supabase/migrations/`. The migration filename was generated by Supabase CLI **2.120.0** with `supabase migration new funagent_memory`. No old schema is imported. The deployment transaction requires a clean database with PostgreSQL 15+, pgvector 0.7+, and the standard Supabase `anon`, `authenticated`, `service_role`, `authenticator` roles.

From source or an independently installed wheel, export the same resource without depending on cwd:

```powershell
uv run --no-sync python -c "from src.memory.deployment import SupabaseSQL; from pathlib import Path; Path('funagent-memory.sql').write_text(SupabaseSQL(), encoding='utf8')"
psql $env:TDD08_SUPABASE_DB_DSN -v ON_ERROR_STOP=1 -f funagent-memory.sql
```

Apply only to the database selected for this application. The SQL deliberately fails if `funagent_private` already exists; it does not overwrite an existing installation. PostgREST must expose `public`; keep `funagent_private` unexposed. The asset explicitly grants the RPC functions and reloads the schema cache.

The `funagent_memory` role receives SELECT/INSERT/UPDATE, sequence USAGE and RPC EXECUTE, with no LOGIN, BYPASSRLS, DELETE or schema CREATE. Signed JWT `app_metadata.funagent_namespace` binds its RLS scope. The authenticator can assume this role. `service_role` receives the same grants on these new objects and supports trusted backend secret keys; its existing Supabase BYPASSRLS privilege is unchanged. It uses the configured namespace passed by the Store. Neither `anon` nor `authenticated` can execute these RPCs or access the private table. The functions use SECURITY INVOKER and an empty search path.

Configure the new source with `store="supabase"`, `kind="episodic"`, `endpoint="https://<project>.supabase.co/rest/v1"`, `namespace`, `credential_env="SUPABASE_SECRET_KEY"` and a nested `embedding` table. A new `sb_secret_...` key is sent as `apikey`, without a non-JWT Bearer token. For a scoped JWT, set `credential_env` to the JWT variable and `api_key_env` to the project's publishable-key variable. Credentials stay in the configuration directory's `.env` or process environment.

Embedding profile contains model, dimensions, query prefix and document prefix. Similarity search materializes namespace/source/metadata/profile filters before computing cosine distance. List and empty-text search read latest records across profiles. The application permits dimensions 1–4096, including the full Qwen3-Embedding-8B output; profile changes require an explicit maintenance rebuild. There is no automatic re-embedding or generated multidimensional index schema. Current search is exact, with namespace/filter indexes, rather than an approximate vector index. pgvector's `vector` storage supports these dimensions; the 2000-dimension limit applies to its HNSW/IVFFlat vector indexes, which this schema does not create.

Run all real contracts in disposable **official Supabase Postgres 17.11.0.004 / PostgREST 16.4** containers:

```powershell
docker pull supabase/postgres:17.11.0.004
docker pull postgrest/postgrest:v16.4
uv sync --locked --extra dev --extra openai --extra embedding --extra supabase --extra supabase-test
uv run --no-sync python scripts/supabase_contract_smoke.py
```

The harness binds random ports to loopback, generates local credentials, deploys the packaged SQL, runs real HTTP/RPC and multi-connection transactions, and removes only its own containers/volumes/network in `finally`. It does not read the checkout `.env` or contact a hosted project.

Default pytest deselects `supabase_integration`. The dedicated job uses `-o addopts= -m supabase_integration`; missing `TDD08_SUPABASE_ISOLATED=1`, database DSN, RPC URL or JWT secret is a failure, never a skip. An independently supplied test environment must already have this deployment and be explicitly isolated.
